05 銘柄スカウター スコア計算方法

このページは scripts/generate_fundamental_scores.ps1（自動取得）と viewer/server.js（手動貼付。同一の閾値・計算式で実装）の現在のコードを そのまま説明したものです。仕様の推測や過去バージョンの記述ではなく、実装コードが正です。

成長性40点
収益性20点
財務20点
企業品質（quality_score）80点
企業品質（quality_score）80点
割安度（valuation_score）20点
総合（total_score_100）100点

企業品質80点 = 成長性40 + 収益性20 + 財務20 − 欠損データペナルティ（後述、最大20点減点・下限0点）
総合100点 = 企業品質（quality_score）80点満点 + 割安度（valuation_score）20点満点

総合ランク 総合100 成長性40 収益性20 財務20 割安20

1. 総合ランク（total_rank_100）

一覧の「総合ランク」列は total_score_100（下記2.）を次の閾値でA〜Eに区分したものです。

ランク条件
A85点以上
B70点以上85点未満
C55点以上70点未満
D40点以上55点未満
E40点未満

実装: Get-TotalRank100（generate_fundamental_scores.ps1）

total_score_100が算出できない場合

valuation_status = insufficient_data（下記6.のcoverage参照）の銘柄は total_score_100・total_rank_100とも算出されず、一覧には「-」と表示されます。 データが少ないことを理由に自動的にE評価やランク最下位にすることはしていません。

旧ランク（quality_rank）との違い
銘柄詳細ページの「旧品質ランク(80点)」＝quality_rankは、企業品質80点満点のみを A(68点以上)〜E(32点未満)で区分した従来からのランクです（下記の閾値・強制ランク上限つき）。 一覧の「総合ランク」列はtotal_rank_100（100点満点）であり、quality_rankとは別物です。 また現在のコードでは、下で説明する「強制ランク上限（減益・赤字予想・自己資本比率30%未満などでA/BをCへ強制的に下げる仕組み）」は quality_rankにのみ適用され、total_rank_100には適用されていません（total_score_100の数値のみで判定）。

参考: 旧quality_rank（企業品質80点満点）の閾値

ランク条件
A68点以上（下記の条件に該当する場合はCへ強制変更）
B56点以上68点未満（同上）
C44点以上56点未満
D32点以上44点未満
E32点未満

次のいずれかに該当する場合、A・Bランクは強制的にCへ引き下げられます（rank_cap）。

  • 営業利益5年成長率がマイナス
  • 経常利益5年成長率がマイナス
  • 自己資本比率が30%未満
  • 会社側が赤字予想を発表している（forecast_loss）

実装: Get-QualityRank / Limit-RankToC（generate_fundamental_scores.ps1）

2. 総合100（total_score_100）

成長性40点
収益性20点
財務20点
割安度20点
総合100点

total_score_100 = quality_score（企業品質80点満点） + valuation_score（割安度20点満点）

企業品質80点の内訳は「成長性40 + 収益性20 + 財務20 − 欠損データペナルティ」です （各項目の詳細は3〜5章、割安度20点の詳細は6章を参照）。

欠損データペナルティ（企業品質80点側）

成長性・収益性・財務で使う主要10項目 （売上高/営業利益/経常利益/当期利益の各5年成長率、ROE、ROIC、自己資本比率、有利子負債比率、営業利益率5年平均、黒字継続年数）のうち 値が取得できていない項目数 × 2点を、成長性+収益性+財務の合計から差し引きます（最大20点減点、0点が下限）。

実装: Get-MissingDataCount / $missingPenalty = min(20, 欠損数×2)（generate_fundamental_scores.ps1）

total_score_100が算出されない条件

valuation_status = insufficient_data（割安度20点の評価可能項目が少なすぎる場合。6章参照）の銘柄は、 valuation_scoreが算出されないためtotal_score_100も算出しません。 「割安度のデータが足りない＝割高（0点）」という扱いはしていません。算出不能として一覧には「-」と表示します。

実装: 380〜385行目付近（generate_fundamental_scores.ps1）

3. 成長性（40点満点）

4つの5年CAGR（年率換算成長率）指標を、それぞれ下表の段階に応じて配点し合計します（合計が40点を超える場合は40点で頭打ち）。

指標満点20%以上12%以上20%未満7%以上12%未満3%以上7%未満0%以上3%未満0%未満 or 欠損
売上高5年成長率8点8.06.44.83.21.60点
営業利益5年成長率12点12.09.67.24.82.40点
経常利益5年成長率10点10.08.06.04.02.00点
当期利益5年成長率10点10.08.06.04.02.00点
合計（上限）40点

各指標が取得できない場合は、マイナス成長と同じ0点として扱われます（欠損だからといって加点も減点もしません。0点扱いです）。

実装: Get-GrowthScore / Get-GrowthMetricScore（generate_fundamental_scores.ps1）。 各成長率自体は scripts/generate_fundamentals.ps1 が直近実績と5年前実績からCAGR（年率換算）で算出しています。

4. 収益性（20点満点）

ROE・ROIC・営業利益率（5年平均）の3指標を段階配点し合計します（合計が20点を超える場合は20点で頭打ち。3指標の満点合計もちょうど20点）。

指標満点条件と点数
ROE（自己資本利益率）7点20%以上→7 / 15%以上→5 / 10%以上→4 / 5%以上→1 / 5%未満・欠損→0
ROIC（投下資本利益率）7点15%以上→7 / 10%以上→5 / 7%以上→4 / 4%以上→1 / 4%未満・欠損→0
営業利益率（5年平均）6点25%以上→6 / 15%以上→4 / 10%以上→3 / 5%以上→1 / 5%未満・欠損→0
合計20点
一覧の「ROE」列は、この収益性スコアで使っているROEの実測値そのものです。ROEは収益性スコアの構成要素でもあります。

実装: Get-ProfitabilityScore（generate_fundamental_scores.ps1）

5. 財務（20点満点）

自己資本比率・有利子負債比率・黒字継続年数の3項目を採点し合計します（合計が20点を超える場合は20点で頭打ち。3項目の満点合計もちょうど20点）。

項目満点条件と点数
自己資本比率9点70%以上→9 / 50%以上→7 / 30%以上→4 / 20%以上→1 / 20%未満・欠損→0
有利子負債比率6点10%以下→6 / 30%以下→4 / 60%以下→2 / 60%超→0 / 欠損時は中立扱いで4点
黒字継続年数5点10年以上→5 / 7年以上→4 / 5年以上→3 / 3年以上→1 / 3年未満・欠損→0
合計20点
自己資本比率は財務20点の中ですでに評価されています（一覧の「自己資本比率」列と同じ実測値を使用）。
有利子負債比率だけは、他の項目と異なり「欠損＝0点」ではなく「欠損＝中立扱いで4点」になります （6点満点中4点＝10%以下と30%以下の中間相当）。

業種補正について: 銀行業等向けに financial_industry_*という別集計（ROE・営業利益率・黒字継続年数・増配年数を使う代替式）が CSVに保存されていますが、これは04_強銘柄追随側が金融業向けに参照するための値であり、 05の一覧・詳細に表示している「財務」スコア自体は業種に関わらず上表の同一計算式です（銀行業でも自己資本比率・有利子負債比率で採点）。

実装: Get-FinancialScore（generate_fundamental_scores.ps1）

6. 割安度（valuation_score・20点満点）

PERやPBRの絶対水準だけで「安い＝加点、高い＝減点」と単純評価すると、高成長株・業績回復途上の銘柄・新規上場銘柄などを 不当に低評価してしまうため、5つの観点（A〜E）に分けて評価し、取得できたデータの範囲内でのみ採点します。

A. 自社過去PER相対評価6点
B. 成長率調整PER（PEG）5点
C. EV/EBITDA4点
D. PBR × ROE3点
E. 52週株価水準2点
合計20点

A. 自社過去PER相対評価（6点）

マネックス銘柄スカウターの「予想PER相対水準（2年）」「予想PER相対水準（5年）」を使います。 これは0〜100の数値で、その銘柄自身の過去2年/5年のPERレンジの中で現在の予想PERがどの位置にあるかを表します （0＝自社の過去レンジで最も割安だった水準、100＝最も割高だった水準）。同業他社・業種平均との比較ではありません。

2年・5年の両方が取得できる場合は「5年水準×0.6 ＋ 2年水準×0.4」で統合し、5年をやや重視します。 どちらか一方のみ取得できる場合はその値をそのまま使います。両方とも欠損（新規上場銘柄など）の場合は評価対象外です。

統合後の水準（0=最安値側〜100=最高値側）点数

20超〜35以下5点
35超〜50以下4点
50超〜65以下3点
65超〜80以下2点
80超〜90以下1点
90超0点

実装: Get-ValuationA（generate_fundamental_scores.ps1） / valA（viewer/server.js）

B. 成長率調整PER / PEG（5点）

第一優先: マネックス銘柄スカウターが計算済みの「予想PEGレシオ」がある場合はその値をそのまま使います。

欠損時のみ自前計算: 予想PER（会社予想）が取得できている場合に限り、 PEG = 予想PER ÷ 利益成長率 を計算します。利益成長率は次の優先順位で採用します。

  1. 予想EPS成長率 ＝ (会社予想EPS − 直近実績EPS) ÷ 直近実績EPS。ただし直近実績EPSが黒字（0超）の場合のみ。
  2. 予想経常利益（コンセンサス）増益率。ただし前年の経常利益実績が黒字（0超）の場合のみ。
異常値対策: 成長率が0%以下、または前年実績が赤字・存在しない場合は「PEGとして意味を持たない」として評価対象外にします （0点にはしません）。成長率が200%を超える場合も、前年比数百〜数千%という極端な回復局面（例: 前年の利益水準が 極端に小さい）とみなして評価対象外にします。
成長率が0%超200%以下の場合のみ採用し、そのうえで60%を上限にクリップしてPEGの分母に使います （例: 実成長率55%→55のまま使用、120%→60に切り下げて使用）。

予想PER自体が欠損している銘柄では、無理に自前PEGを計算せず評価対象外とします。

D. PBR × ROE（3点）

pbr_roe_ratio = PBR ÷ ROE(%) を計算します。高ROE企業は高PBRでも正当化されるため、PBR単独では判定しません。 ROEが0以下（赤字）の場合はこの指標が数学的に意味を持たないため評価対象外とし、0点にはしません。 PBRが取得できない場合も評価対象外です。

実装: Get-ValuationD（generate_fundamental_scores.ps1） / valD（viewer/server.js）

E. 52週株価水準（2点）

0〜100の水準（52週高値・安値の中で現在株価がどの位置にあるか。低いほど52週安値に近い＝割安方向）を、補助的に採点します。 企業価値そのものではなく株価の位置にすぎないため配点は2点のみです。全銘柄で取得できています。

75.6超0点

実装: Get-ValuationE（generate_fundamental_scores.ps1） / valE（viewer/server.js）

データが少ない銘柄の扱い（valuation_coverage）

A〜Eのうち評価対象外（データ欠損）の項目は、20点の分母からも除外します。「データがない＝割高として0点」にはしません。

評価可能項目の満点合計available_max_score
実際の獲得点earned_score
割安度20点earned_score ÷ available_max_score × 20

ただし available_max_score が9点未満の場合は、根拠として不十分（＝評価不足）とみなし、 valuation_scoreそのものを算出しません（0点にもしません）。

coverage（=available_max_score ÷ 20）valuation_status意味
70%以上normal十分なデータで算出
45%以上70%未満reference算出はするが参考値扱い
45%未満（available_max_score が9点未満）insufficient_data算出しない（valuation_score・total_score_100ともN/A）

実装: Get-ValuationResult（generate_fundamental_scores.ps1） / computeValuation（viewer/server.js）

目標株価・目標株価乖離率について

銘柄詳細ページに表示している目標株価・目標株価乖離率は参考値です。アナリスト予想は業績修正や株価上昇に 後追いすることがあり、これをそのまま加点すると循環参照的な評価になるため、valuation_scoreの計算には一切使用していません。
